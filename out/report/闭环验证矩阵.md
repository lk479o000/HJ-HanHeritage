## 五、最终结论

1. **后台 → 游客端**：崖墓、石棺、全景的新增/修改/下架/删除已全部经公开接口实时反映到游客端；公告在管理登录页可见。断链根因（游客端读静态数据 + 业务接口全被 JWT 拦截）已通过 `/api/v1/visitor/*` 公开只读接口 + 前端接线消除。
2. **游客行为 → 后台**：首页、崖墓详情、石棺导览、石棺视图切换、全景浏览均产生操作日志与在线访客，崖墓/石棺/全景浏览量自增，仪表盘可消费。
3. **数据约束**：`status`/`delFlag` 语义在两侧统一，下架即游客不可见；全景分类已做映射。
4. **仍断链或有意保留**：
   - 游客首页：页面仅承载分布图底图，没有崖墓图片展示位，因此崖墓封面/多图落库后首页无需也无可接线位置（详情页已接线）；如需首页展示需另行改版原型。
   - 游客端公告位：原型无承载位，未新增（设计不适用）。
   - 游客登录日志：游客无登录体系，只记操作日志，不伪造登录日志（设计不适用）。
   - 媒体文件：上传走 `uploads/` 并已纳入忽略规则；后台移除只解除库内引用，物理文件需通过 `npm run uploads:clean`（dry-run）或 `npm run uploads:clean:apply`（实际删除）清理。
5. **验证数据已清理**：删除 CM-TEST、HG-TEST、室外测试全景、闭环测试公告；公开量恢复崖墓 13 / 石棺 28 / 全景 5（含新增室外种子、不含草稿） / 公告 1。演示残留同步清空：CM-05 `cover_image=null`、`model_url=null`、`biz_cliff_image` 0 条（测试上传的 2 张 PNG 物理文件已从 `uploads/` 移除），游客详情回退 `FALLBACK_IMAGES` 与「该崖墓三维模型待补充」空态；CF-01 `map_left/map_top=null`，游客导览回退 `markerPosition`（实测 37.3543% / 31.9258%，非 82.5% / 18.5%）；室外全景种子（id 8「崖墓群室外环境全景」）保留。
6. **模型地址校验与空态**：新增 `GET /api/v1/cliffs/model/check`，站内路径检查 `uploads/` 与 `public/` 物理文件，外链按 HEAD→GET Range 探测（5 秒超时）。后台崖墓编辑弹窗提供「校验地址」按钮即时提示；新增/保存时服务端再次校验，`/models/custom-tomb-test.glb` 返回 400「模型文件不存在，请检查路径」，可达地址正常保存。游客详情仅在 `model_url` 有值时渲染 `model-viewer`，未配置时显示「该崖墓三维模型待补充」，不再引用 `modelviewer.dev` 占位模型，也不影响已配置模型的加载。
