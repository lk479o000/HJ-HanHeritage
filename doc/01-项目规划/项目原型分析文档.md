# 合江汉代画像石棺数字化保护与展示利用项目 — 原型分析文档

## 一、项目概述

本项目为"合江汉代画像石棺数字化保护与展示利用（二期）"的原型系统，面向四川省泸州市合江县的汉代崖墓群及画像石棺文物资源，提供**游客端三维互动展示**与**管理后台可视化运营**两大核心能力。原型以纯静态 HTML/CSS/JavaScript 构建，不使用任何前端框架，以最小化依赖支撑完整功能演示。

### 项目定位

- **游客端（prototype/）**：面向公众的文物数字化展示门户，含崖墓分布地图、石棺三维模型浏览、全景漫游、崖墓群专属页面等。
- **管理后台（prototype-admin/）**：面向博物馆/文物管理人员的可视化运营系统，含业务数据管理、组织权限、日志监控、运维监控、系统配置等完整后台能力。

## 二、技术架构

### 2.1 技术栈

| 层次 | 技术选型 | 说明 |
|------|----------|------|
| 前端框架 | 无框架，原生 HTML/CSS/JavaScript ES5 | 最小依赖，纯静态页面 |
| 三维模型渲染 | Google `<model-viewer>` v3.5.0 (jsDelivr CDN) | 支持 GLB/GLTF 格式，拖拽旋转、滚轮缩放、双指平移 |
| 全景漫游 | Pannellum v2.5.6 (jsDelivr CDN) | 等距柱状全景图渲染，支持 360°×180° 环视 |
| 数据持久化 | localStorage + 内存 | 原型阶段所有数据存于浏览器本地存储与会话内存 |
| 字体 | Google Fonts (Noto Serif SC / Noto Sans SC) | 标题与正文中文字体 |
| 前端路由 | iframe 壳 + sessionStorage | 管理后台通过 iframe 壳实现类 SPA 导航 |

| `cliff-data.js` | 崖墓群标点数据（13处） |

## 三、游客端功能分析

### 3.1 首页 — 崖墓分布地图总览

**文件**：`prototype/index.html`

**功能描述**：
- 展示合江县汉代崖墓分布图（`hejiang-han-cliff-distribution.png` 作为底图）
- 13 处崖墓群以标点形式叠加在地图上
- 每个标点显示编号和名称，点击跳转至对应的崖墓专属页面
- 大耳朵崖墓群（CM-05）带有 `featured` 标记
- 底部固定三个核心功能入口：全景漫游、石棺解读、大耳朵崖墓群

**技术实现**：
- `home-map.js` 根据 `cliff-data.js` 中的坐标数据动态生成地图标点按钮
- 标点位置以百分比定位，可适配不同尺寸底图
- CSS 层叠定位实现标点覆盖

### 3.2 石棺解读 — 三维模型浏览

**文件**：`prototype/coffin.html`

**功能描述**：
- 28 具画像石棺的三维模型浏览，支持编号选择、上一具/下一具切换
- 使用 Google `<model-viewer>` 渲染 GLB/GLTF 三维模型
- **五种展示模式**：
  1. 三维模型（默认）
  2. 数字正射影像图（JPG）
  3. 数字拓片图
  4. 数字线划图
  5. 数字信息增强图
- **三维交互工具**：
  - 放大/缩小（轨道半径调节）
  - 自动旋转
  - 复位
  - 全屏视口
  - 背景取色器
- **石棺尺寸测量**：在三维模型表面点选两点估算直线距离（模型坐标单位）
- 默认最佳观察角度：斜前方，已限制底面观察
- 侧边面板展示石棺简介（年代、出土地、画像内容主题）

**技术实现**：
- 使用 Google `<model-viewer>` 自定义元素，支持 `camera-controls`、`camera-orbit`、`field-of-view` 等属性
- `positionAndNormalFromPoint` API 实现模型表面取点测量
- 28 具石棺数据采用模拟生成（年代分期、出土地点轮换、画像主题轮换）
- 可通过 URL 参数 `?coffin=N` 直接定位到指定石棺
- 与崖墓群页面联动：`?from=ear` 参数时返回按钮指向崖墓群页面

### 3.3 石棺分布导览

**文件**：`prototype/coffin-map.html`

**功能描述**：
- 在合江崖墓分布图上叠加 28 个石棺模拟标点
- 点击标点跳转至对应石棺详情页面
- 标点按 4 个簇生成（模拟聚类分布效果）

### 3.4 崖墓群专属页面

**文件**：`prototype/cliff-detail.html`

**功能描述**：
- 13 处崖墓群各自专属页面，通过 URL 参数 `?cliff=N` 区分
- **两种展示模式**：
  1. 崖墓群三维模型（支持拖拽旋转/缩放）
  2. 图片查看（支持上一张/下一张/放大）
- **固定视点跳转**：崖墓近景、崖墓全景
- **三维交互工具**：放大/缩小、自动旋转、复位、全屏视口、背景取色
- 只有大耳朵崖墓群（id=5）展示完整三维功能；其他崖墓群自动切换到图片模式
- 大耳朵崖墓群页面侧栏提供关联石棺入口

**技术实现**：
- `cliff-data.js` 中的 13 处崖墓数据驱动
- 非大耳朵崖墓群时自动隐藏三维相关控件，仅保留图片查看

### 3.5 大耳朵崖墓群（特色点位）

**文件**：`prototype/ear-tomb.html`

**功能描述**：
- 大耳朵崖墓群的专属特色页面
- 展示无人机实景三维模型
- 固定视点跳转（近景/全景）
- 石棺入口链接（石棺 1、石棺 2）
- 三维交互工具齐全

### 3.6 博物馆全景漫游

**文件**：`prototype/panorama.html`

**功能描述**：
- 合江县汉代画像石棺博物馆全景漫游
- **四种全景类型**（Tab 切换）：
  1. 空中（无人机/高架等距柱状全景）
  2. 地面（馆区步行视点）
  3. 室内（展厅实景）
  4. 室外（馆外环境与庭院）
- 每种类型包含 2 个场景点位
- 支持 360°×180° 拖拽环视与缩放
- 下方缩略图条切换不同点位
- 室内场景使用局部视角（非标准等距图）

**技术实现**：
- 使用 Pannellum 全景库渲染
- 支持 `equirectangular` 等距柱状投影与 `partial` 局部全景
- 与后台「博物馆全景管理」绑定资源

## 四、管理后台功能分析

### 4.1 登录页

**文件**：`prototype-admin/login.html`

**功能描述**：
- 左侧英雄区展示项目品牌（文物数字化馆藏 · 合江汉代画像石棺）

**文件**：`prototype-admin/index.html` + `admin-layout.js`

**功能描述**：
- 侧栏 + 顶栏 + iframe 主内容区的经典后台布局

- 顶栏显示当前用户昵称和退出入口

### 4.3 首页概览

**文件**：`prototype-admin/dashboard.html`

**功能描述**：

- 快捷入口按钮：崖墓管理、石棺管理、博物馆全景管理、资源管理
- **公告栏**：展示最近公告
- **数据统计**：资源类型分布条形图、近 7 天登录趋势 Sparkline 图
- **日志与在线**：最新操作列表、在线用户列表
- 支持独立模式和嵌入模式（iframe 壳内）两种渲染

### 4.4 崖墓管理

**文件**：`prototype-admin/cliff.html`

**功能描述**：
- **Tab 1 - 展示与查询**：
  - 合江崖墓分布地图（底图 + 可点击标点）
  - 标点点击打开崖墓信息弹窗
  - 崖墓群台账列表（含名称、地址、坐标、面积、级别、文物保护单位名称、年代、类别、文物构成、简介、状态）
  - 按状态、乡镇筛选
  - 按名称/地址/编号搜索
  - 新增崖墓群、编辑字段、导出 CSV
- **Tab 2 - 大耳朵 · 墓口点位**：
  - 在无人机实景三维模型上标注墓口位置（最多 6 个）
  - 支持"在模型上拾取坐标"模式
  - 墓口列表（序号、名称、模型内坐标/节点、操作）

**技术实现**：
- 地图标点基于 `cliff-data.js` 中 13 处崖墓数据
- 三维模型使用 `<model-viewer>` + 拾取交互

### 4.5 石棺管理

  - **数字成果图**（4 种类型，每种可含多张）：
    - 数字正射影像图（JPG）
    - 数字拓片图
    - 数字线划图
    - 数字信息增强图
    - 支持上一张/下一张导航、缩略图切换、全屏放大
- 新增石棺、导出功能

**技术实现**：
- 28 具石棺模拟数据含完整藏品登记字段
- 成果图按类型分组管理
- 三维模型嵌入在弹窗中

**功能描述**：

## 六、关键技术要点

### 6.1 三维模型渲染
- 使用 Google `<model-viewer>` Web Component，无需 Three.js 二次开发
- 支持 GLB/GLTF 格式、PBR 材质、环境贴图
- 原型阶段使用公开示例模型占位，正式环境替换为文物实景三维模型

### 6.2 全景漫游
- 使用 Pannellum 库渲染等距柱状全景
- 支持标准 360° 全景和局部非标准等距图
- 管理端与游客端共享相同的分类/视点配置逻辑

### 6.3 数据持久化
- **localStorage**：菜单树（含菜单管理配置）、公告列表、个人资料
- **内存 Store**：组织架构（部门/角色/岗位/用户）、日志/在线数据
- 原型阶段所有数据仅存于浏览器，重启即恢复默认

### 6.4 iframe 壳架构
- 后台通过 `index.html` 中的 iframe 壳加载各业务页面
- 每个业务页面同时支持独立模式（侧栏+顶栏自渲染）和嵌入模式（`embed=1`）
- `embed.js` 检测嵌入模式并适配 CSS

## 七、当前原型局限性

1. **无后端服务**：所有数据存于浏览器内存/localStorage，无 API 接口
2. **无真实鉴权**：登录表单提交即进入后台，无用户认证机制
3. **三维模型占位**：使用公开示例模型（Astronaut/Horse/Robot）占位，非真实文物模型
4. **全景图片占位**：多数全景使用 Pannellum 官方示例图，仅室内场景使用本地模拟图
5. **无数据库**：数据无持久化存储，刷新或重启浏览器后恢复默认
6. **无构建流程**：纯手写 HTML/CSS/JS，无模块化、无打包、无 TypeScript
7. **模拟数据**：石棺年代、出土地、画像主题均为规则轮换生成，需替换为真实藏品数据
8. **无测试**：无自动化测试、无单元测试、无 E2E 测试
9. **无响应式适配**：虽有 `viewport-fit=cover` 设置，但未做移动端完整适配
10. **无国际化**：仅中文，无 i18n 方案

## 十、总结

本项目原型以**纯静态前端技术**完整演示了"合江汉代画像石棺数字化保护与展示利用"的全部功能链路：

- **游客端**：13 处崖墓群地图分布 → 28 具石棺三维模型浏览（含尺寸测量）→ 4 类全景漫游
- **管理端**：完整的业务数据管理 + 组织架构授权 + 日志审计 + 运维监控 + 系统配置

原型在功能完整性上已达到较高水平，但距离生产就绪还有大量工作（后端接口、数据库、鉴权、真实数据、测试、CI/CD 等），以下为人天预估文档。
