# 合江汉代画像石棺数字化保护与展示利用项目 — 开发人天预估

## 一、预估说明

本文档基于原型系统（`prototype/` + `prototype-admin/`）的完整功能范围，按**从零开发到生产就绪**进行人天预估。当前原型为纯静态 HTML/CSS/JavaScript 演示系统，无后端、无数据库、无鉴权、使用占位数据。正式开发需要全面重构。

> **实现说明（2026-11-06）**：本文为规划期人天评估，文中 Spring Boot/JVM 等选型仅为当时的候选方案；实际后端采用 NestJS + Prisma，前端采用 Vue3 + Element Plus。评估数字不代表最终交付进度。

### 预估前提假设
- 团队具备 Java/Spring Boot 或 Node.js 后端开发能力
- 团队具备 Vue3/React 前端开发能力
- 文物三维模型、全景图片、成果图等素材已由数据采集团队完成
- 服务器、域名、OSS 对象存储等基础设施已就绪
- 1 人天 = 8 小时有效工作时间

### 关键技术选型说明

#### 三维渲染：Three.js 替代方案
> **Google model-viewer 在中国可用性问题**：由于 Google 服务在中国大陆存在访问不稳定问题，**强烈建议使用 Three.js 替代**。
- **优势**：完全开源、无外部依赖、高度可定制、社区活跃、支持所有主流 3D 格式
- **替代方案**：Three.js + GLTFLoader + OrbitControls + DRACOLoader（压缩支持）

#### UI 组件库：避免 Element Plus 坑
> **Element Plus 常见问题**：表格虚拟滚动问题、表单校验复杂、弹窗层级冲突、自定义主题困难
- **推荐替代**：
  - **Naive UI**：性能优秀，API 简洁，文档清晰
  - **PrimeVue**：企业级组件库，功能完备，坑少
  - **Mantine**（React）：灵活可控，无过度封装

#### 字体方案：移除 Google Fonts 依赖
> **Google Fonts 访问问题**：建议使用本地字体或国内 CDN
- **方案**：
  - 下载 Noto Serif SC / Noto Sans SC 字体文件，放入项目静态资源
  - 使用 font-display: swap 确保加载体验
  - 备选：使用思源字体或站酷开源字体

#### AI 服务：国内可用方案
> **LLM 服务选择**：优先选择国内可访问的服务
- **推荐**：阿里云通义千问、百度文心一言、深度求索、豆包
- **向量数据库**：Milvus（国内团队维护）、Qdrant（可自托管）、阿里云向量数据库
- **部署**：私有化部署或使用国内云厂商服务

## 八、总结

本项目从原型到生产就绪的完整开发工作量预估为 **214 人天**（不含 15%~20% 缓冲），按 4 人团队配置预计工期约 **4 个月**。

核心工作集中在：
1. **前端开发（79.5 人天，37%）**：19 个管理后台页面 + 6 个游客端页面的 Vue3 重构
2. **后端开发（58.5 人天，27%）**：Spring Boot 全部 API 模块
3. **测试（24 人天，11%）**：单元/集成/E2E/性能/安全测试全覆盖
4. **数据与联调（23 人天，11%）**：真实文物数据录入与前后端对接

前端工作量最大的原因是原型包含 **25 个独立 HTML 页面**，每个页面都有复杂的交互逻辑（三维模型操作、全景漫游、树形结构管理、权限配置、富文本编辑等），需要完整重写为 Vue3 SPA 架构。
