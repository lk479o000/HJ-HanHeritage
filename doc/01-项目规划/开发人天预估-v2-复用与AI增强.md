# 合江汉代画像石棺数字化保护与展示利用项目 — 开发人天预估（v2：复用原型 + AI 增强）

## 一、版本说明

本文档为第二版评估，相比初版（`开发人天预估.md`）的核心变化：

| 维度 | 初版（v1） | 本版（v2） |
|------|-----------|-----------|
| 原型利用 | 视为参考，全面重写 | **部分代码直接复用**，能省则省 |
| 技术栈 | Vue3 + Spring Boot（同） | 同，但迁移策略更温和 |
| 功能范围 | 原型功能 1:1 还原 | 原型功能 + **AI 智能能力增强** |
| 数据 AI 化 | 无 | 在文物展示与管理全链路注入 AI |

### 2.2 中复用度（参考改写）

| 类别 | 说明 |

## 三、AI 能力增强方案

本项目的核心是"文物数字化保护与展示利用"，AI 在以下环节带来质的提升：

### 3.1 AI 基础设施（所有 AI 功能的前提）

| 编号 | 任务 | 人天 | 说明 |
|------|------|------|------|
| A1.1 | LLM 服务接入 | 3 | 对接大模型 API（通义千问/DeepSeek/文心一言等），统一调用网关，支持流式输出与 Function Calling |
| A1.2 | 向量数据库搭建 | 2 | Milvus/Qdrant/Elasticsearch 向量索引，存储文物描述的 Embedding（text-embedding-3-small / bge-large-zh） |
| A1.3 | RAG 检索增强生成框架 | 3 | 文档切片 → 向量化 → 相似检索 → 上下文注入 Prompt 的完整链路 |
| A1.4 | Prompt 管理平台 | 2 | Prompt 模板库、版本管理、A/B 测试、效果评估面板（管理后台新增菜单项） |
| A1.5 | AI 调用日志与监控 | 2 | Token 消耗统计、响应延迟监控、异常重试、成本核算看板 |
| **小计** | | **12** | |

|------|------|------|------|
| A2.1 | 博物馆知识库构建 | 3 | 整理合江崖墓/石棺/汉代历史/画像主题的权威资料，分词+RAG索引；支持管理员后台增删改知识条目 |
| A2.2 | 游客端 AI 问答浮窗 | 3 | 浮动聊天窗口组件，支持流式输出 Typing 动画、历史对话记录（localStorage）、问题建议快捷入口 |
| A2.3 | 管理端 AI 问答面板 | 2 | 在石棺/崖墓详情弹窗中嵌入 AI 问答Tab，管理员可验证 AI 回答准确性并反馈纠错 |
| A2.4 | 多轮对话上下文管理 | 2 | 对话摘要压缩、话题切换检测、引用溯源（回答标注来源知识库条目） |
| A2.5 | 反馈闭环 | 1.5 | 👍👎 评价收集 → 低分回答自动入审核队列 → 管理员修正知识库 |
| **小计** | | **11.5** | |

### 3.3 AI 文物图像识别与分析

**场景**：上传石棺画像/拓片图后，AI 自动识别纹饰内容（车马出行、宴饮乐舞、神兽护棺等）、分类并打标签。

| 编号 | 任务 | 人天 | 说明 |
|------|------|------|------|
| A3.1 | 视觉模型接入 | 2 | 多模态大模型（Qwen-VL/GPT-4V）API 封装，支持图片→结构化描述 |
| A3.2 | 画像纹饰自动识别 | 3 | 上传成果图 → AI 自动识别纹饰类别（车马/宴饮/神兽/祥瑞/礼制场景）、人物数量、构图特征，生成结构化标签 JSON |
| A3.3 | 纹饰标签管理 | 2 | 标签体系定义（二级分类树：一级=主题大类，二级=具体纹饰），支持人工修正与模型微调反馈 |
| A3.4 | 以图搜图 | 3 | 基于 CLIP/视觉Embedding 的相似纹饰检索："上传一张拓片，找出所有类似纹饰的石棺" |
| A3.5 | 文物损伤检测 | 2.5 | AI 识别画像/石棺实物的裂缝、剥落、风化区域，标注损伤类型与严重程度，生成检测报告 |
| **小计** | | **12.5** | |

## 六、核心结论

> **230.5 人天，仅比初版增加 16.5 人天（+8%），即在"复用原型代码"和"加入 AI 能力"两相抵消后，总体增量很有限。**

原因分析：

| 因素 | 影响 | 幅度 |
|------|------|------|
| 原型代码复用（CSS/JS/数据结构/交互模式） | **节省 ~28.5 人天** | -13% |
| AI 基础设施 + 11 个 AI 功能模块 | **增加 ~45 人天** | +21% |
| 净影响 | **+16.5 人天** | +8% |

复用主要体现在：
- 13 个 CSS 文件全部可复用或微调，省去"从设计稿写样式"
- Store/数据结构直接映射为数据库表设计和 API 契约，减少需求沟通
- 菜单树/路由/权限模型已验证，架构设计量减少
- 页面 DOM 结构 → Vue 模板迁移，比从零写组件快 30%~40%
