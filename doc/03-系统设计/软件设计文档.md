## 1. 引言

### 1.1 文档目的

本文档为合江汉代画像石棺数字化保护与展示利用项目的软件设计文档（Software Design Document，SDD），旨在整合项目架构设计、接口设计、数据结构设计等关键设计决策，作为开发团队的核心参考文档。

本文档与需求规格说明书（SRS）配套使用，SRS定义“做什么”，SDD定义“怎么做”。两个文档共同构成项目的技术蓝图，指导后续开发工作顺利开展。

### 1.2 设计原则

系统设计遵循以下核心原则，以确保系统的可靠性、可扩展性和可维护性。

模块化设计原则要求系统按功能划分为独立模块，模块间通过清晰接口通信，降低耦合度，便于独立开发和测试。模块划分需符合单一职责原则，每个模块只负责一类功能。

可扩展设计原则要求系统架构预留扩展接口，新功能可在不修改现有代码情况下添加。数据模型支持字段扩展，业务逻辑支持插件机制。

高性能设计原则要求系统在架构层面考虑性能优化，包括缓存策略、异步处理、懒加载等手段，确保系统在负载下仍能保持良好响应速度。

安全性设计原则要求系统将安全作为设计核心，从架构层面防范常见安全威胁，包括认证授权、输入验证、加密传输等。

### 1.3 技术选型

系统采用前后端分离架构，技术选型兼顾技术先进性、团队适配性和国内可访问性。

前端技术选型采用Vue3配合TypeScript和Vite构建工具。Vue3相比Vue2在性能、TypeScript支持和Composition API上有显著提升。TypeScript提供类型检查能力，可减少运行时错误。Vite提供极快的开发服务器启动和热更新体验。UI组件库选用Element Plus，与现有原型设计风格高度一致（深色侧栏、蓝色主调），迁移成本低，生态成熟。管理后台基于Vue Element Admin框架进行二次开发，确保与Demo视觉风格统一。三维渲染使用Three.js替代Google model-viewer，确保国内访问稳定性。全景渲染使用Pannellum库，纯JS实现，无外部依赖。

后端技术选型提供三套方案供团队根据实际情况选择。方案一采用Node.js NestJS框架，配合Prisma ORM和MySQL数据库，全栈TypeScript开发效率高。方案二采用Java Spring Boot 3.2+框架，配合Spring Data JPA和MySQL数据库，适合对Java技术栈熟悉的团队。方案三采用Node.js NestJS配合PostgreSQL，适合需要更强JSON支持的项目。

基础设施采用MySQL 8.0作为主数据库，Redis 7作为缓存和会话存储，阿里云OSS作为文件存储，Docker容器化部署。

## 2. 系统架构设计

### 2.1 整体架构

系统采用前后端分离架构，整体分为前端层、网关层、应用层、数据层、基础设施层五个层级。

前端层运行在用户浏览器中，负责页面渲染和用户交互。前端部署于Nginx服务器，通过CDN加速静态资源分发。用户请求首先到达CDN，未命中缓存则回源到Nginx服务器。

网关层部署在Nginx服务器上，负责静态资源服务、反向代理、负载均衡和SSL终结。Nginx配置域名路由规则，将API请求转发到后端应用服务器，将静态资源请求直接返回。

应用层运行后端应用服务，负责处理业务逻辑。应用服务器部署多个实例，通过Nginx负载均衡分发请求。应用服务包含API服务和AI服务两个独立模块，AI服务在需要时调用外部LLM API。

数据层包括MySQL数据库集群、Redis缓存集群和阿里云OSS对象存储。MySQL采用主从复制架构实现读写分离。Redis集群部署多个节点保证缓存高可用。OSS存储所有文件资产，通过CDN加速访问。

基础设施层包括服务器资源、网络配置、监控告警等运维支撑。所有服务部署于Docker容器中，通过docker-compose或Kubernetes进行编排管理。

### 2.2 模块划分

系统按功能划分为以下核心模块。

内容展示模块负责游客端的内容展示功能，包括首页地图、石棺解读、崖墓详情、全景漫游等页面。该模块从数据库获取内容数据，调用三维渲染和全景渲染服务进行展示。

三维浏览模块封装Three.js的加载、渲染和交互功能。该模块接收三维模型文件URL，加载GLB/GLTF格式模型，提供旋转、缩放、测量等交互操作。该模块同时处理模型压缩和LOD分级以优化加载性能。

全景漫游模块封装Pannellum的全景展示功能。该模块接收全景图片URL和热点配置，渲染全景场景，支持视角控制、热点跳转、场景切换等交互。

AI服务模块封装与大语言模型和向量数据库的交互逻辑。该模块提供智能问答接口，接收用户问题，检索相关知识，构造Prompt，调用LLM生成回答。同时提供图像识别接口，处理图片上传和内容识别。

后台管理模块提供系统管理功能，包括数据管理、用户管理、系统配置等子模块。该模块包含完整的CRUD操作，调用文件存储服务管理资源文件。

### 2.3 数据流向

系统典型数据流向如下。

游客浏览石棺三维模型时，数据流向为用户浏览器发起HTTP请求，Nginx接收并转发到应用服务器，应用服务器查询数据库获取石棺元数据，返回数据到浏览器，前端使用Three.js从OSS获取三维模型文件并渲染展示。

管理员上传石棺图片时，数据流向为管理员在浏览器选择图片文件，前端将图片直传到OSS获取预签名URL，图片上传完成后，前端调用API保存元数据到数据库。

用户进行智能问答时，数据流向为用户输入问题并提交，前端将问题发送到AI服务，AI服务将问题向量化并检索向量数据库，构造Prompt并调用LLM API，LLM返回生成的回答，前端以流式方式展示回答内容。

### 3.2 路由设计

前端路由采用Vue Router管理，分为游客端路由和管理端路由两套独立的路由表。

游客端路由为公开访问，无需认证。路由配置如下。

| 路径 | 组件 | 名称 | 说明 |
|------|------|------|------|
| / | Home | 首页 | 崖墓分布地图 |
| /coffin/:id | Coffin | 石棺解读 | 石棺详情和三维模型 |
| /cliff/:id | CliffDetail | 崖墓详情 | 崖墓群专属页面 |
| /big-ear | BigEarCliff | 大耳朵崖墓 | 大耳朵崖墓专题页 |
| /panorama | Panorama | 全景漫游 | 博物馆全景漫游 |

管理端路由需要认证，路由配置通过后端返回的菜单数据动态生成。路由守卫检查用户登录状态和权限标识，未登录或无权限时重定向到登录页。

### 3.3 状态管理

前端状态管理采用Pinia，按功能划分为以下Store。

用户Store管理用户登录状态，包含用户信息、Token、登录状态等。提供登录、登出、刷新Token等方法。

权限Store管理权限数据，包含路由权限、按钮权限、角色信息等。提供权限初始化、权限校验等方法。

应用Store管理全局应用状态，包含侧栏折叠状态、标签页列表、全局配置等。

字典Store管理字典数据，包含系统字典、枚举值等。提供字典查询和缓存方法。

### 3.4 组件设计

#### 3.4.1 通用组件

通用组件库包含以下基础组件，按功能分类组织。

布局组件包括Header组件（顶部导航栏）、Sidebar组件（侧边栏菜单）、Breadcrumb组件（面包屑导航）、Tabs组件（标签页组件）。布局组件接收配置参数，支持主题定制。

表单组件包括Input组件、Select组件、DatePicker组件、Upload组件等。表单组件统一封装表单校验逻辑，支持异步校验和自定义规则。

表格组件包括Table组件、Pagination组件。表格组件封装分页、排序、筛选等常用功能，提供插槽支持自定义列。

对话框组件包括Modal组件、Drawer组件、Message组件。对话框组件提供统一的动画效果和过渡效果。

#### 3.4.2 业务组件

业务组件包括以下与项目功能相关的组件。

地图组件封装地图加载和标注功能，支持崖墓群标注点的显示和交互。使用高德地图JS SDK实现。

三维浏览组件封装Three.js加载和渲染功能。组件接收模型URL作为参数，自动处理加载状态、错误处理、交互绑定等逻辑。组件提供缩放、旋转、重置、全屏等操作按钮。

全景浏览组件封装Pannellum渲染功能。组件接收全景图片URL和热点配置，自动处理全景场景渲染。组件提供视角控制、场景切换、热点跳转等交互功能。

石棺卡片组件展示单个石棺的简要信息。组件接收石棺数据作为props，渲染卡片布局，点击卡片可跳转到详情页。

成果图画廊组件展示石棺成果图。组件支持多类型切换、缩略图浏览、全屏查看等功能。

### 3.5 Three.js封装

Three.js封装为可复用的组合式函数和组件，降低业务代码复杂度。

组合式函数useThree接收容器元素和配置参数，返回Three.js场景对象和操作方法。函数自动处理场景创建、相机配置、灯光设置、渲染循环、资源清理等逻辑。

组件CofficModel3D封装三维模型加载和展示。组件接收modelUrl、autoRotate等props，自动处理模型加载进度、加载失败等情况。组件暴露ref供父组件获取Three.js对象进行高级控制。

### 3.6 样式系统

样式系统采用CSS变量 + Sass实现，支持主题定制。

样式变量定义在variables.scss中，包含颜色、字体、间距、阴影等设计令牌。游客端采用国风主题配色，以深棕色系为主色调，搭配金色点缀。管理端采用清爽的浅色主题。

全局样式定义在global.scss中，包含重置样式、字体加载、滚动条样式等基础样式。

组件样式采用Scoped CSS或CSS Modules方式编写，避免样式污染。

## 4. 后端设计

### 4.1 项目结构

后端项目采用NestJS或Spring Boot框架，以NestJS为例，项目结构如下。

```
hanheritage-api/
```

### 4.2 模块设计

后端按功能划分为多个模块，每个模块包含Controller、Service、Entity、DTO等组件。

认证模块负责用户登录、登出、Token刷新等认证相关功能。模块提供JWT令牌生成和验证能力，支持登录限流和账号锁定。

用户模块负责用户账号的CRUD操作，包括用户信息管理、密码修改、头像上传等功能。

角色模块负责角色定义和权限配置。角色关联菜单权限和接口权限，定义数据访问范围。

部门模块负责组织架构管理。部门支持树形层级结构，提供级联查询和操作能力。

崖墓模块负责崖墓群数据管理。崖墓包含基本信息、地理坐标、关联墓口点等信息。

石棺模块负责石棺数据管理。石棺包含详细信息、关联崖墓、成果图、三维模型等。

全景模块负责全景场景管理。全景包含场景信息、图片资源、视点配置、热点标注等。

资源模块负责文件资源管理。资源采用树形目录结构，支持多种文件类型。

日志模块负责操作日志和登录日志的记录和查询。日志通过AOP切面自动记录。

监控模块负责系统运行状态采集。包括在线用户、会话管理、服务状态、缓存状态等信息。

AI模块负责AI服务的接入和调用。模块封装LLM网关、向量检索、RAG流程等逻辑。

### 4.3 核心服务设计

#### 4.3.1 认证服务

认证服务处理用户登录逻辑。服务接收账号密码，验证账号状态和密码正确性，生成JWT令牌并返回。JWT包含用户ID、角色列表、过期时间等信息。

服务同时处理Token刷新逻辑。检查Token是否临近过期，若是则生成新Token。Token默认有效期2小时，刷新Token有效期延长2小时。

#### 4.3.2 权限服务

权限服务处理权限校验逻辑。服务解析请求Header中的Token，获取用户信息和权限列表。服务检查用户是否有权访问请求的接口或菜单。

权限类型分为菜单权限和接口权限。菜单权限控制左侧菜单显示，接口权限控制API调用权限。权限标识采用规范命名，如"system:user:list"表示系统模块用户列表权限。

#### 4.3.3 文件服务

文件服务处理文件上传和存储。服务接收上传请求，验证文件类型和大小，将文件流上传到阿里云OSS。上传成功后返回文件访问URL。

服务同时处理文件删除、复制、移动等操作。对于已上传的文件，服务记录文件元数据到数据库，支持后续管理和统计。

#### 4.3.4 AI服务

AI服务封装AI能力调用逻辑。服务分为LLM网关、向量检索、RAG流程三个子模块。

LLM网关模块负责与外部LLM API通信。模块支持多LLM提供商（通义千问、文心一言、DeepSeek等），提供统一的调用接口。模块处理请求构造、响应解析、错误处理、重试逻辑等。

向量检索模块负责向量数据库操作。模块提供文档向量化、相似度检索、向量更新等功能。模块支持Milvus和Qdrant两种向量库，提供统一的抽象接口。

RAG流程模块负责检索增强生成流程。模块接收用户问题，查询向量库获取相关上下文，构造Prompt调用LLM生成回答。模块同时记录对话历史，支持多轮对话。

### 4.4 异常处理

后端采用统一异常处理机制。业务异常抛出自定义业务异常类，包含错误码和错误消息。系统异常由全局异常过滤器捕获，统一处理并返回标准化错误响应。

错误码采用分段设计，不同模块占用不同码段。认证模块错误码为1xxxx，系统模块错误码为2xxxx，业务模块错误码为3xxxx，AI模块错误码为4xxxx。

常见业务异常包括资源不存在（404）、权限不足（403）、参数错误（400）、业务规则违反（422）等。

## 5. 数据设计

### 5.1 数据库选型

系统采用MySQL 8.0作为主数据库。MySQL 8.0支持JSON数据类型、窗口函数、CTE等新特性，适合复杂查询场景。MySQL 8.0的InnoDB引擎提供事务支持和行级锁，保证数据一致性。

系统同时使用Redis 7作为缓存和会话存储。Redis提供高性能的键值存储，支持多种数据结构，可用于缓存热点数据、存储会话信息、实现分布式锁等场景。

### 5.2 命名规范

数据库命名遵循以下规范。数据库名称统一使用小写字母，采用下划线分隔词，如hejiang_coffin。表名称使用小写字母，采用下划线分隔词，如sys_user、biz_cliff。前缀标识表类型，sys_表示系统表，biz_表示业务表，log_表示日志表。

字段命名遵循以下规范。字段名称使用小写字母，采用下划线分隔词。主键字段统一命名为id。创建时间字段命名为create_time，更新时间字段命名为update_time。创建人字段命名为create_by，更新人字段命名为update_by。删除标记字段命名为del_flag，软删除时置为1。版本号字段命名为version，用于乐观锁。

索引命名遵循以下规范。普通索引命名为idx_字段名，如idx_user_name。唯一索引命名为uk_字段名，如uk_user_account。联合索引命名为idx_字段1_字段2。

### 5.3 核心表结构

#### 5.3.1 系统模块

系统模块包含用户表、角色表、部门表、菜单表等核心系统表。

用户表（sys_user）存储用户账号信息，包含账号、密码、姓名、手机、邮箱、头像、部门ID、状态等字段。密码使用bcrypt加密存储。状态字段标记账号是否启用。

角色表（sys_role）存储角色定义，包含角色名称、角色标识、角色类型、数据范围、排序号、状态等字段。角色标识用于权限校验，如SYS_ADMIN、EDITOR等。

用户角色关联表（sys_user_role）存储用户与角色的多对多关系。

角色菜单关联表（sys_role_menu）存储角色与菜单的多对多关系，包含菜单权限和接口权限。

部门表（sys_dept）采用邻接表模型存储树形结构，包含部门名称、上级ID、排序号等字段。通过递归查询获取部门树。

菜单表（sys_menu）存储系统菜单配置，包含菜单名称、图标、上级ID、路由地址、组件路径、排序号、类型（菜单/按钮）等字段。

#### 5.3.2 业务模块

业务模块包含崖墓表、石棺表、全景表、资源表等业务数据表。

崖墓表（biz_cliff）存储崖墓群信息，包含编号、名称、经度、纬度、面积、级别、年代、简介、状态、创建时间、更新时间等字段。编号字段唯一，如CM-01。

墓口表（biz_entrance）存储墓口点位信息，包含崖墓ID、X坐标、Y坐标、Z坐标、朝向、简介等字段。

石棺表（biz_coffin）存储石棺信息，包含编号、名称、崖墓ID、年代、类型、尺寸、质地、保存状况、详细描述、缩略图URL、创建时间、更新时间等字段。编号字段唯一，如CK-01。

石棺成果图表（biz_coffin_image）存储石棺成果图，包含石棺ID、图片URL、图片类型（正射/拓片/线划/增强）、排序号、创建时间等字段。

石棺模型表（biz_coffin_model）存储石棺三维模型，包含石棺ID、模型URL、格式、文件大小、创建时间等字段。

全景表（biz_panorama）存储全景场景信息，包含名称、类型（空中/地面/室内）、位置、简介、图片URL、状态、创建时间、更新时间等字段。

全景视点表（biz_panorama_viewpoint）存储全景视点配置，包含全景ID、视点名称、经度、纬度、高度、创建时间等字段。

全景热点表（biz_panorama_hotspot）存储全景热点标注，包含全景ID、热点类型（场景跳转/信息点）、热点配置（目标场景ID或文字信息）、位置X、位置Y、创建时间等字段。

资源表（biz_resource）采用路径枚举模型存储目录和文件，包含资源名称、资源类型（目录/文件）、上级ID、文件URL、文件大小、MIME类型、创建时间、更新时间等字段。

#### 5.3.3 日志模块

日志模块包含登录日志表和操作日志表。

登录日志表（log_login）存储登录记录，包含用户名、登录时间、IP地址、操作系统、浏览器、登录结果、失败原因等字段。

操作日志表（log_operation）存储操作记录，包含操作人、操作时间、操作类型、操作对象ID、操作描述、请求方法、请求URL、请求参数、响应状态、IP地址、执行时长等字段。操作日志通过AOP切面自动记录。

### 5.4 索引设计

数据库索引设计需平衡查询性能和写入性能。常用查询条件字段建立索引，包括用户表的账号和部门ID、石棺表的崖墓ID和编号、崖墓表的编号和状态等。联合索引需考虑字段顺序，将区分度高的字段放在前面。

主键自动建立唯一索引。外键字段建立索引以加速关联查询。频繁排序的字段建立索引。

### 5.5 缓存设计

Redis缓存设计如下。Token缓存存储用户Token和用户信息，Key格式为token:{token}，TTL为2小时。用户信息缓存存储热点用户数据，Key格式为user:{userId}，TTL为24小时。字典缓存存储系统字典数据，Key格式为dict:{dictType}，TTL为1小时。权限缓存存储用户权限标识，Key格式为perms:{userId}，TTL为1小时。

### 5.6 数据字典

系统使用以下数据字典定义枚举值。

状态字典定义通用状态，包括启用（1）、停用（0）。

石棺类型字典定义石棺分类，包括完整（1）、残缺（2）、待修复（3）。

成果图类型字典定义成果图分类，包括正射影像（ortho）、拓片（rubbing）、线划图（line）、增强效果图（enhanced）。

全景类型字典定义全景分类，包括空中全景（aerial）、地面全景（ground）、室内全景（indoor）、其他（other）。

资源类型字典定义资源分类，包括图片（image）、三维模型（model）、全景图片（panorama）、文档（document）、视频（video）、音频（audio）、压缩包（archive）。

## 6. 接口设计

### 6.1 接口规范

所有API接口遵循RESTful风格，采用JSON格式进行数据交换。

接口路径采用资源名词复数形式，如/api/v1/users表示用户资源。HTTP方法表示操作类型，GET表示查询，POST表示新增，PUT表示更新，DELETE表示删除。

接口版本通过URL路径管理，如/api/v1/表示第一版接口。新版本接口发布到/api/v2/路径。

### 6.2 认证方式

接口认证采用Bearer Token方式。客户端在请求Header中携带Authorization字段，格式为Bearer {token}。无Token或Token无效时返回401未授权错误。

登录接口不要求认证，其他接口均需认证。部分公开接口（如获取公开崖墓信息）可通过配置跳过认证。

### 6.3 统一响应格式

接口统一响应格式如下。

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

code为业务状态码，200表示成功，其他值表示错误。message为提示信息，成功时为"success"，错误时为错误描述。data为响应数据，查询接口返回具体数据，新增接口返回新记录ID，更新删除接口返回布尔值或影响行数。

分页接口响应格式如下。

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "list": [],
    "total": 100,
    "page": 1,
    "pageSize": 10
  }
}
```

### 6.4 错误码定义

系统错误码采用五位数字，前两位表示模块，后三位表示具体错误。

认证模块错误码以1开头，10001表示账号不存在，10002表示密码错误，10003表示账号已锁定，10004表示Token已过期，10005表示Token无效。

系统模块错误码以2开头，20001表示无权限访问，20002表示参数错误，20003表示数据不存在，20004表示数据已存在，20005表示操作失败。

业务模块错误码以3开头，30001表示崖墓不存在，30002表示石棺不存在，30003表示全景不存在，30004表示资源不存在，30005表示关联数据不存在。

AI模块错误码以4开头，40001表示AI服务不可用，40002表示请求超时，40003表示模型响应错误，40004表示向量检索失败。

### 6.5 分页参数

分页接口支持以下请求参数。page表示当前页码，从1开始，默认值为1。pageSize表示每页记录数，默认值为10，最大值为100。orderBy表示排序字段，默认按ID倒序。orderDirection表示排序方向，支持asc和desc。

## 7. AI服务设计

### 7.1 AI架构

AI服务采用RAG（检索增强生成）架构，结合知识库检索和语言模型生成，提供精准的智能问答能力。

RAG架构分为三个阶段。检索阶段将用户问题向量化，在向量数据库中检索相关知识片段。生成阶段将检索到的知识片段和问题拼接成Prompt，调用语言模型生成回答。后处理阶段对生成的回答进行格式化处理，提取参考来源，添加引用标注。

### 7.2 LLM网关

LLM网关封装与外部语言模型的通信逻辑。网关支持多模型接入，通过配置切换不同模型提供商。网关处理请求构造、响应解析、错误处理、重试等逻辑。

支持的模型包括通义千问（阿里云）、文心一言（百度）、DeepSeek（深度求索）等。模型选择考虑回答质量、响应速度、成本等因素。生产环境建议配置主备模型，主模型不可用时自动切换到备用模型。

### 7.3 知识库

知识库存储文物相关知识，用于RAG检索。知识库内容包括崖墓和石棺的详细描述、历史背景、文化意义等文本数据。知识经过分块处理，每个知识块约500字符，保留完整语义。

知识块存储在向量数据库中，通过向量化模型转换为向量表示。向量数据库支持高效的相似度检索，返回与问题最相关的知识块。

### 7.4 向量数据库

向量数据库选型考虑性能、易用性和部署方式。推荐使用Milvus（国内团队维护）或Qdrant（可完全私有化部署）。向量维度根据向量化模型确定，一般为768或1024维。

向量数据库提供以下核心操作。upsert操作批量插入或更新向量数据。search操作进行相似度检索，返回top-k最相似结果。delete操作删除指定向量数据。

### 7.5 Prompt工程

Prompt工程设计直接影响回答质量。系统采用结构化Prompt模板，包含系统指令、上下文信息、对话历史、用户问题四个部分。

系统指令定义AI角色和行为规范，如“你是一个专业的文物讲解员，用简洁易懂的语言回答用户问题”。上下文信息插入检索到的知识片段，作为回答的依据。对话历史保存最近N轮对话，支持多轮交互。用户问题为当前用户的提问内容。

### 7.6 流式响应

智能问答接口支持流式响应（SSE），提升用户体验。用户发送问题后，回答内容实时推送显示，无需等待完整回答生成完成。

流式响应格式如下。

```
data: {"type": "chunk", "content": "这具"}
data: {"type": "chunk", "content": "石棺上"}
data: {"type": "chunk", "content": "的车马"}
...
data: {"type": "sources", "refs": [{"id": 1, "title": "合江汉代画像石棺研究"}, {"id": 2, "title": "崖墓考古报告"}]}
data: {"type": "done"}
```

## 8. 安全设计

### 8.1 认证安全

用户密码采用bcrypt算法加密存储。bcrypt是一种自适应哈希函数，支持配置计算强度，默认强度为10。密码比对时使用bcrypt.compare进行验证。

登录接口实现防暴力破解机制。记录用户连续登录失败次数，超过阈值（默认5次）后锁定账号15分钟。锁定记录存储在Redis中，设置过期时间自动解锁。

JWT令牌采用签名验证，令牌内容Base64编码但不加密，因此不在令牌中存储敏感信息。令牌默认有效期2小时，临近过期时前端调用刷新接口获取新令牌。

### 8.2 授权安全

系统采用RBAC（基于角色的访问控制）模型。用户关联角色，角色关联权限，权限分为菜单权限和接口权限。

菜单权限控制前端路由和UI元素的显示隐藏。接口权限控制后端API的访问控制。双重验证确保权限控制的有效性。

数据范围控制限制用户可访问的数据范围。数据范围分为全部数据、本部门数据、本部门及下级数据、仅本人数据四级。

### 8.3 输入安全

所有用户输入在服务端进行校验。使用参数校验注解（如@NotBlank、@Size、@Pattern）验证必填项、长度限制、格式要求。校验失败时返回明确的错误信息。

SQL注入防护使用参数化查询或ORM框架的查询方法，避免拼接SQL字符串。ORM框架自动处理参数转义。

XSS防护对用户输入进行HTML转义，将特殊字符替换为HTML实体。响应输出时也对内容进行转义，防止脚本注入。

### 8.4 传输安全

全站启用HTTPS，确保数据传输加密。证书使用Let's Encrypt免费证书或商业证书。HTTP请求自动重定向到HTTPS。

API接口启用CORS策略，限制允许的请求来源。前端域名添加到白名单，非白名单请求被拒绝。

### 8.5 日志审计

所有操作记录详细日志，包括操作人、操作时间、操作内容、操作结果、IP地址等信息。日志采用异步写入，不影响主业务性能。

日志存储保留6个月，超期日志自动归档或删除。日志数据不可修改删除，只能查询和导出。

## 9. 部署架构

### 9.1 容器化部署

所有服务采用Docker容器化部署。容器化提供环境一致性、快速部署、易于扩展等优势。

前端服务构建Nginx镜像，将Vue3构建产物复制到镜像中。容器启动时加载Nginx配置，提供静态资源服务和反向代理。

后端服务构建应用镜像，基于Node.js或Java基础镜像。容器启动时运行应用进程，监听指定端口。

数据库和Redis使用官方镜像，配置持久化存储。

### 9.2 Docker Compose编排

开发环境和小型部署使用Docker Compose编排管理。编排文件定义所有服务、网络、卷等资源。

```yaml
version: '3.8'
services:
  frontend:
    build: ./frontend
    ports:
      - "80:80"
    depends_on:
      - backend
    networks:
      - app-network

  backend:
    build: ./backend
    ports:
      - "8080:8080"
    environment:
      - DB_HOST=mysql
      - REDIS_HOST=redis
    depends_on:
      - mysql
      - redis
    networks:
      - app-network

  mysql:
    image: mysql:8.0
    ports:
      - "3306:3306"
    volumes:
      - mysql-data:/var/lib/mysql
    environment:
      - MYSQL_ROOT_PASSWORD=xxx
    networks:
      - app-network

  redis:
    image: redis:7
    ports:
      - "6379:6379"
    volumes:
      - redis-data:/data
    networks:
      - app-network

volumes:
  mysql-data:
  redis-data:

networks:
  app-network:
    driver: bridge
```

### 9.3 生产环境部署

生产环境采用Kubernetes编排管理。Kubernetes提供自动扩缩容、自愈、滚动更新等能力。

生产环境架构如下。前端服务部署3个Pod，通过NodePort或LoadBalancer暴露服务。Nginx Ingress Controller处理外部流量路由。

后端服务部署多个Pod，通过Service暴露服务。配置HPA（水平Pod自动扩缩容），根据CPU使用率自动调整Pod数量。

MySQL采用主从复制架构，写操作访问主库，读操作访问从库。配置StatefulSet管理有状态服务。

Redis采用主从+哨兵或集群模式，保证缓存高可用。

### 9.4 CI/CD流程

持续集成和持续部署流程如下。开发者提交代码到Git仓库，触发CI流水线。CI流水线执行代码构建、单元测试、代码检查等步骤。构建成功后生成镜像并推送到镜像仓库。

代码合并到主分支后，触发CD流水线。CD流水线执行镜像拉取、配置更新、滚动部署等步骤。部署过程中进行健康检查，确保新版本正常运行后再切换流量。
