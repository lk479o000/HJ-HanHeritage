# 部署手册（本地与生产）

本文档给出当前仓库可直接执行的部署步骤，配套文件：

| 文件 | 作用 |
|------|------|
| `hanheritage-api/.env.example` | 后端环境变量示例（端口、MySQL、JWT、Redis） |
| `hanheritage-web/.env.example` | 前端环境变量示例（本地演示开关、开发代理目标） |
| `deploy/start-prod.sh` | 生产构建与启动脚本（前端构建 → 后端生成/构建 → 迁移 → 启动） |
| `deploy/nginx/hanheritage.conf` | Nginx 站点配置（静态托管 + `/api`、`/uploads` 反代） |
| `deploy/health-check.sh` | 部署后健康检查脚本 |

## 一、架构与端口

```
浏览器 → Nginx :80/:443
              ├─ /             → hanheritage-web/dist（游客端 + 管理后台，SPA）
              ├─ /api/         → 127.0.0.1:3083（NestJS，全局前缀 /api/v1）
              ├─ /uploads/     → 127.0.0.1:3083（后端静态托管上传文件）
              └─ /healthz      → 探测后端公开接口
NestJS → MySQL :3306（Prisma）
       → Redis :6379（可选，仅系统监控相关页面使用）
```

## 二、环境要求

- Node.js >= 20（含 npm；前端 Vite 8 与后端 NestJS 11 均要求 Node 20 以上）
- MySQL 8.x，字符集 `utf8mb4`
- Redis 7.x（可选；未部署时监控页会提示不可用，不影响业务主流程）
- Nginx 1.20+（生产反向代理；本地开发不需要）

## 三、环境变量

首次部署先复制示例文件：

```bash
cp hanheritage-api/.env.example hanheritage-api/.env
cp hanheritage-web/.env.example hanheritage-web/.env
```

后端 `hanheritage-api/.env`：

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `PORT` | `3083` | 后端监听端口，与 Nginx upstream 保持一致 |
| `DATABASE_URL` | `mysql://user:password@127.0.0.1:3306/han_coffin_db` | Prisma 连接串，生产使用最小权限账号 |
| `JWT_SECRET` | 占位值 | 生产必须替换为随机值（建议 >= 32 位） |
| `JWT_EXPIRES_IN` | `2h` | 登录令牌有效期 |
| `REDIS_HOST` / `REDIS_PORT` | `127.0.0.1` / `6379` | 可选，Redis 信息页使用 |

前端 `hanheritage-web/.env`：

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `VITE_LOCAL_MODE` | `false` | 生产构建必须为 `false`，否则游客端与后台使用本地演示数据 |
| `VITE_API_PROXY_TARGET` | `http://localhost:3083` | 仅 `npm run dev` 的代理目标；生产由 Nginx 反代，不参与构建 |

注意：

- 仓库只提交 `.env.example`，不要提交包含真实密码的 `.env`。
- 启动脚本通过 shell 读取 `.env`，值建议使用双引号包裹，避免使用 `$`、反引号等会被 shell 展开的字符。
- 若此前 `hanheritage-api/.env` 已被纳入版本库，请执行 `git rm --cached hanheritage-api/.env` 停止跟踪，并轮换其中的数据库密码与 JWT 密钥。

## 四、首次部署

### 1. 创建数据库

`prisma migrate deploy` 只执行迁移，不会创建数据库，需先建库：

```bash
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS han_coffin_db DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
```

### 2. 构建并启动

```bash
deploy/start-prod.sh
```

脚本执行顺序固定为：

1. 校验 Node 版本、`hanheritage-api/.env` 是否存在、前端是否误开本地演示模式；
2. `npm ci` 安装前端与后端依赖（迁移需要 Prisma CLI，因此后端保留 devDependencies）；
3. `npm run build` 构建前端，产物在 `hanheritage-web/dist`；
4. `prisma generate` 生成 Prisma Client；
5. `npm run build` 构建后端，产物在 `hanheritage-api/dist/src/main.js`；
6. `prisma migrate deploy` 执行数据库迁移；
7. 以前台进程启动后端（工作目录为 `hanheritage-api`，保证 `/uploads` 指向正确目录）。

可选环境变量：

| 变量 | 作用 |
|------|------|
| `SKIP_INSTALL=1` | 依赖已安装时跳过 `npm ci` |
| `SKIP_WEB_BUILD=1` | 仅更新后端时跳过前端构建 |
| `SKIP_API_BUILD=1` | 直接使用已有 `dist`，跳过 Prisma 生成与后端构建 |
| `ALLOW_LOCAL_MODE=1` | 允许以 `VITE_LOCAL_MODE=true` 构建演示版（生产禁用） |
| `API_ENV_FILE` | 自定义后端环境变量文件路径 |

脚本第 7 步为前台进程，适合调试或交给 supervisor 托管；长期运行建议使用 systemd（见第六节）。

手动等效命令：

```bash
cd hanheritage-api
npm ci && npm run db:generate && npm run build && npm run db:migrate:deploy
npm run start:prod          # 等价于 node dist/src/main.js

cd ../hanheritage-web
npm ci && npm run build
```

### 3. 演示数据（仅测试/演示环境）

```bash
cd hanheritage-api && npm run db:seed
```

生产环境不要导入演示数据。默认管理员账号见 `hanheritage-api/README.md`，上线前必须修改密码。

## 五、Nginx 反向代理

```bash
sudo mkdir -p /var/www/hanheritage-web
sudo rsync -a --delete hanheritage-web/dist/ /var/www/hanheritage-web/
sudo cp deploy/nginx/hanheritage.conf /etc/nginx/conf.d/hanheritage.conf
sudo vi /etc/nginx/conf.d/hanheritage.conf   # 修改 server_name、root、证书路径
sudo nginx -t && sudo systemctl reload nginx
```

配置要点：

- `try_files $uri $uri/ /index.html`：vue-router history 模式必需，否则直接访问 `/admin/login` 等路由会 404。
- `client_max_body_size 600m`：后端上传上限为 500MB，Nginx 需留余量，否则大文件返回 413。
- `/api/`、`/uploads/` 均反代到 `127.0.0.1:3083`，不要另起路径前缀。
- 前后端同域部署时浏览器不触发跨域；后端 `enableCors(origin: true)` 仅用于直连场景，Nginx 不要重复添加 CORS 响应头。
- 反代默认保留 `Host`、`Origin` 等请求头，不要清除，否则 JWT/来源判断可能异常。
- 多实例部署时，`uploads` 目录需改为共享存储，或由 Nginx 以 `alias` 直接托管同一目录。
- 后端游客埋点当前使用 `req.ip`，经 Nginx 反代后记录的是代理地址；如需真实访客 IP，需在后端启用 `trust proxy`（涉及业务代码，本次未改动）。

## 六、进程守护（systemd 示例）

发布时先完成构建与迁移：

```bash
cd hanheritage-api && npm ci && npm run db:generate && npm run build && npm run db:migrate:deploy
cd ../hanheritage-web && npm ci && npm run build
sudo rsync -a --delete hanheritage-web/dist/ /var/www/hanheritage-web/
```

`/etc/systemd/system/hanheritage-api.service`：

```ini
[Unit]
Description=HanHeritage API
After=network.target mysql.service

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/HJ-HanHeritage/hanheritage-api
EnvironmentFile=/opt/HJ-HanHeritage/hanheritage-api/.env
ExecStart=/usr/bin/node dist/src/main.js
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now hanheritage-api
```

## 七、健康检查

```bash
deploy/health-check.sh
# 自定义地址
API_URL=http://127.0.0.1:3083 WEB_URL=http://127.0.0.1 deploy/health-check.sh
```

脚本检查两项：

1. `GET /api/v1/visitor/cliffs` 返回 `{"code":200,...}`（该接口会查询数据库，同时可反映 MySQL 连通性）；
2. 前端首页返回 HTTP 200。

其他检查方式：

```bash
curl http://127.0.0.1/healthz                  # 经 Nginx 探测后端
mysqladmin -h 127.0.0.1 ping                   # MySQL 连通性
redis-cli -h 127.0.0.1 ping                    # Redis 连通性（可选）
```

## 八、常见问题

| 现象 | 排查方向 |
|------|---------|
| 后端启动报缺少 `dist/src/main.js` | 先执行 `npm run build`；产物路径是 `dist/src/main.js` 而不是 `dist/main.js` |
| `prisma migrate deploy` 报数据库不存在 | 先按第四节建库；确认 `DATABASE_URL` 指向正确实例 |
| 页面 404 / 刷新后 404 | Nginx 未配置 `try_files ... /index.html` |
| 上传大文件返回 413 | 调整 Nginx `client_max_body_size` |
| 游客端显示演示数据 | 前端 `.env` 中 `VITE_LOCAL_MODE=true`，生产应改为 `false` 后重新构建 |
| 后台监控页 Redis 不可用 | 未部署 Redis 或 `REDIS_HOST`/`REDIS_PORT` 配置错误；不影响主流程 |
| 上传文件 404 | 后端工作目录不是 `hanheritage-api`，导致静态目录指向错误 |

## 九、容器化现状

当前仓库**没有**可直接使用的容器化产物：不存在 `Dockerfile`、`docker-compose*.yml`、`.dockerignore`，因此本次未引入 Docker 文件，避免与现有裸机/Nginx 部署方式并存两套未经验证的方案。

`doc/06-运维部署/部署运维与性能优化分析报告.md` 第 1.4 节的 Docker Compose 编排属于早期设计稿，其中镜像（如 `openjdk:17-jre-slim`、`/actuator/health`）与本项目 NestJS 技术栈不匹配，不能直接使用。

如需容器化，至少需要补充：

1. `hanheritage-api/Dockerfile`：Node 20 多阶段构建，保留 Prisma CLI 以执行 `migrate deploy`，挂载 `/app/uploads`；
2. `hanheritage-web/Dockerfile`：Node 构建阶段 + Nginx 运行阶段，复用 `deploy/nginx/hanheritage.conf`（容器内 upstream 改为服务名）；
3. `.dockerignore`（排除 `node_modules`、`dist`、`.env`、`uploads`）；
4. `docker-compose.yml`：api、web、mysql、redis（可选），配置 `healthcheck` 与数据卷；
5. 容器健康检查命令：`curl -f http://127.0.0.1:3083/api/v1/visitor/cliffs`。
